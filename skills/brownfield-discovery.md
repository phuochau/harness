# Skill: Brownfield Discovery

Use when adopting the workflow in an existing project or before changing an
unfamiliar codebase.

## Steps

1. Read existing entrypoints: README, agent instructions, package scripts, CI,
   tests, app entrypoints, and architecture docs.
2. Map product surfaces: UI, API, CLI, workers, jobs, integrations, and
   deployment surfaces.
3. Map validation commands: build, test, lint, typecheck, E2E, security, QA, and
   deploy checks.
4. Identify risky areas: missing tests, auth, authorization, data model,
   external providers, fragile modules, and unclear ownership.
5. Record current conventions before proposing changes.
6. Choose one bounded change to prove the workflow.

## Output

- Brownfield discovery note or request.
- Validation map.
- Risk notes.
- First bounded task recommendation.
