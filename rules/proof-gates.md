# Proof Gate Rules

1. A brief is not ready unless proof is named.
2. A ready brief should not contain unresolved `NEEDS CLARIFICATION` markers.
3. A task is not ready unless it has local done criteria.
4. A task must trace to a request, brief, acceptance criterion, finding, or QA
   case.
5. Builder proof is required before review when possible.
6. Review must check scope, behavior, security/data risk, contracts, and proof.
7. Verification must record pass, fail, blocked, or not applicable.
8. A blocked proof must record exact command/check, reason, risk, and next-best
   evidence.
9. Trace must record proof and gaps before completion.
