# Proof Gate Rules

1. A brief is not ready unless proof is named.
2. A ready brief should not contain unresolved clarification markers.
3. A task is not ready unless it has local done criteria.
4. A task must trace to a request, brief, acceptance criterion, finding,
   experiment result, or QA case.
5. Production implementation tasks must include TDD pairs or a recorded
   exception.
6. Builder proof is required before review when possible.
7. Review must check scope, behavior, security/data risk, contracts, TDD
   evidence or exception, and proof.
8. Verification must record `passed`, `failed`, `blocked`, `not_applicable`,
   or `risk_accepted`.
9. A blocked proof must record exact command/check, reason, risk, and next-best
   evidence.
10. An experiment is not complete unless it records hypothesis, success
   criteria, proof, result, and promotion or cleanup decision.
11. Trace must record proof and gaps before completion.
